# Why are we here?

As a design student with no coding background, I used to see programming as very logic and different from my focus on visual design and storytelling. Today, with generative AI capable of writing code on demand, the motivation for designers to learn programming seems even less obvious. However, Dylan Beattie’s talk, The Art of Code, completely shifted my perspective. Beattie demonstrates that code is fundamentally an artistic medium and a form of creative expression, not mere technical labor. While AI can handle syntax execution, it cannot replace computational thinking. For non-technical designers, learning to code is about exploring new frontiers of design and enhancing the appeal of my creative work.

During hisDylan Beattie talk, he showcased generative art created by Robert Felker using Flutter. For designers without a coding background, tools like Figma and digital brushes typically produce static images. Code, however, allows direct control over dynamic particles, interactive systems, and 3D rendering, pushing visual aesthetics beyond the limits of a flat canvas.

Beattie’s mention of Conway’s Game of Life also shifts how we define design. A few simple rules, when executed by a computer, can generate complex and elegant life forms. This moves modern design away from merely drawing final results toward designing underlying rules. Designers who understand code apply computational thinking. They learn to design states and logic, allowing interfaces to respond dynamically to user data rather than relying on fixed layouts.

teamLab provides a practical example of this approach. This interdisciplinary collective writes algorithms to build interactive installations that respond in real time to human touch and movement, rather than relying on pre-rendered videos. This connects to Alan McKee’s (2014) idea of the 'Spectacular', where technology creates rich sensory experiences. By treating code as a creative tool, teamLab moved beyond static screens to orchestrate large-scale visual environments, demonstrating how programming can expand the scope of design.

Machines can generate code on demand, but they require precise instructions. In my own experience, working professionals confirm that while designers do not need to become full-stack developers, grasping the basics of HTML, CSS, or JavaScript remains crucial. Since almost everything we design eventually becomes a digital product through code, this technical awareness helps bridge the gap between design and development. Designers who understand programming logic can read data structures and component relationships, translating these into clear design directives. It also allows us to understand technical constraints, design feasible solutions, and communicate effectively with engineers. Furthermore, they can use Python to automate asset processing, such as batch-editing images. Even though AI tools can speed up coding, they cannot replace a fundamental understanding of how components are structured. Ultimately, this shifts the designer's role from a passive executor to a creator who can direct AI and ensure quality in the final output.

Ultimately, learning to code is about expanding creative freedom, not worrying about machines. In practical design work, understanding basic programming logic ensures that visual concepts are technically feasible. It bridges the communication gap with software engineers and helps designers understand how modern AI tools work. As Dylan Beattie demonstrated in The Art of Code, programming can generate music, write poetry, and build interactive experiences. With AI now handling the heavy burden of manual syntax, designers have a rare opportunity. They can step back from technical labor and fully embrace code as a dynamic medium for art, system design, and creative expression.
