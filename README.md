# Why are we here?

As a design student with no coding background, I used to see programming as very logic and different from my focus on visual design and storytelling. Today, with generative AI capable of writing code on demand, the motivation for designers to learn programming seems even less obvious. However, Dylan Beattie’s talk, The Art of Code, 

completely shifted my perspective. Beattie demonstrates that code is fundamentally an artistic medium and a form of creative expression, not mere technical labor. While AI can handle syntax execution, it cannot replace computational thinking. For non-technical designers, learning to code is about exploring new frontiers of design and enhancing the appeal of my creative work.

During hisDylan Beattie talk, he showcased generative art created by Robert Felker using Flutter. For designers without a coding background, tools like Figma and digital brushes typically produce static images. Code, however, allows direct control over dynamic particles, interactive systems, and 3D rendering, pushing visual aesthetics beyond the limits of a flat canvas.

Beattie’s mention of Conway’s Game of Life also shifts how we define design. A few simple rules, when executed by a computer, can generate complex and elegant life forms. This moves modern design away from merely drawing final results toward designing underlying rules. Designers who understand code apply computational thinking. They learn to design states and logic, allowing interfaces to respond dynamically to user data rather than relying on fixed layouts.

Machines can generate code on demand, but they require precise instructions. Designers who grasp programming logic can read data structures and component relationships, translating these into clear design directives. They can also use Python to automate asset processing, such as batch-editing images. This shifts their role from passive executors to creators who can direct AI and ensure quality in the final output.
